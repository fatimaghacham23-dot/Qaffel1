# Qaffel Design & Product Rules

## Product Philosophy

Qaffel: The Sovereign Design ManifestoVersion 2.0 | Premium Financial OperationsI. Product Philosophy: The "Operational Calm"Qaffel is not a tool; it is a high-fidelity infrastructure. It should feel like a physical object—weighted, purposeful, and permanent.The Aesthetic Anchor: Spatial Minimalism. Use depth to convey importance. Surfaces should feel like layered physical cards, not flat pixels.The Emotional State: Informed Confidence. The user should never wonder "did that work?" or "where is my money?"The Benchmark: The precision of Linear, the tactile nature of Apple Wallet, and the invisible complexity of Stripe.II. The Spatial UI System (The Z-Axis)We do not use "flat" design. We use layered logic to define hierarchy.Surface 0 (The Void): The background. Deep, neutral, slightly recessed.Surface 1 (The Canvas): The primary work area. Subtle grain or noise to prevent "digital flatness."Surface 2 (The Component): Cards and inputs. High-contrast borders ($0.5px$ to $1px$) instead of heavy shadows.Surface 3 (The Focus): Modals and drawers. Use dynamic blur (glassmorphism) strictly for background occlusion to maintain focus, never as a primary decorative element.III. Typography & Numerical TensionIn finance, numbers are the hero. They must be treated with architectural precision.The Stack: A high-end, variable geometric sans (e.g., Inter, Geist, or SF Pro).Tabular Figures: Mandatory. All currency and data tables must use font-variant-numeric: tabular-nums;. Numbers must never "jump" when changing.Optical Sizing: Use smaller tracking for headings and increased letter-spacing for tiny captions to ensure premium readability.Semantic Weights: Use Medium (500) for primary actions and Regular (400) for data. Avoid Bold (700+) except for critical status alerts.IV. Color: Semantic NeutralityWe use a "Leveled Gray" scale. Pure black (#000) is forbidden; use deep obsidian to maintain soft contrast.The Palette: 90% Grayscale (Neutrals). 10% Accents.The Qaffel Blue: A restrained, deep cobalt for "Primary" actions. No neon.Financial Semantics:Success (Paid): Emerald/Sage (Calm, not vibrating).Warning (Pending): Amber/Ochre (Cautionary, not alarming).Danger (Overdue): Crimson/Terra Cotta (Urgent but professional).Interactive State: Every interactive element must have a defined hover, active, and focused state using subtle luminosity shifts.V. Lebanese Market: The "Trust-First" UXDesigning for Lebanon requires solving for "The Informal Gap."The WhatsApp Bridge: "Share to WhatsApp" is the primary CTA. Receipts must be generated as high-fidelity, "Save to Image" cards that look professional when sent over chat.The Proof-of-Payment Workflow: Uploading a Whish/OMT screenshot is a high-stakes moment. Use a "Scanning..." micro-interaction to show the system is working, even if manual review is required. It builds perceived value.Currency Dualism: Support LBP and USD side-by-side with clear, real-time exchange rate labeling. Never hide the rate used for a transaction.The "Human" Touch: Provide "Template" messages for WhatsApp (e.g., "Hi, here is the payment link for Invoice #102...") to reduce friction for the business owner.VI. Micro-Interactions & HapticsPhysical Feedback: On mobile, use selectionHaptic for toggles and impactLight for successful button presses.The "Velocity" Rule: Animations must be <200ms. Use Cubic Bezier $(0.4, 0, 0.2, 1)$ for all transitions. No "bouncing."Skeleton States: Never show a blank screen. Use shimmering pulse skeletons that match the exact spatial layout of the incoming data.VII. Public Interface: The "Payment Portal"The /pay and /receipt pages are the user's only interaction with the brand.Zero-Distraction: Remove all navigation. The only focus is the "Amount Due" and "Payment Method."Institutional Trust: Use "Locked" icons on sensitive data. Display clear "Verified by Qaffel" branding to reassure the end-client.Print Perfection: The CSS @media print must be flawless. Receipts should look like high-end physical stationery when printed to PDF.VIII. Engineering "Premium" StandardsThe "No-Jank" Policy: All lists must be virtualized if >100 items. 60FPS scrolling is a requirement, not a goal.Offline-First Perceptions: Use Optimistic UI updates. When a user marks an invoice as "Sent," it should reflect immediately in the UI while the API call happens in the background.The "Edge" Case Rule: Design for the "Zero State." The app should look beautiful when it's empty, using instructional placeholders that guide the user's first $10$ seconds.The Qaffel Gold Standard"Does this feel like it was built by a global bank, or a weekend coder?"If it feels like a template, delete it. If it feels like an OS, ship it.
